> **The system since the microservices refactor:** one address for the app (**gateway :8080** — the receptionist), two service buildings behind it (**auth-service :8081** — the bouncer, 18 auth routes; **core-service :9000** — the vault room, 56 routes incl. the RC-1 accept-invite exception), sharing **one Neon PostgreSQL database** and one encrypted vault volume. Cross-service JWT validation works because both services read the same `JWT_SECRET`.

## Individual defence formula (everyone)

1. **Pitch (≤ 1 min):** what I own → the hard problem inside it → the mechanism → the proof (a live demo or a greppable artefact).
2. **Analogies (3 ready):** explain your hardest concepts to a non-technologist — the gateway is the receptionist, auth is the bouncer, core is the vault room, an OTP is a VIP wristband, step-up auth is a bank vault (full sets per student in `DEFENCE_GUIDE.md`).
3. **Q&A (3 deep):** the three questions an examiner is most likely to ask *you*, rehearsed word-for-word.
4. **Bridge, never bluff:** "that's Student N's area — here's how my part feeds it." The bridge map is at the bottom of `DEFENCE_GUIDE.md`.
5. **Own your numbers:** 74 logical routes (56 core + 19 auth) · 3 runtimes · 15 tables · 12 migrations (core only) · 45 screens · 216+18 features · 8 pinned libraries · Expo SDK 58 with `expo-doctor` 20/20.
6. **Universal answers:** why no Spring (brief + transparency) · why microservices + a shared DB (Strangler Fig; free-tier RAM/connection budgets; ACID stays in one place) · what the gateway does (forward untouched, 502 when a building is down, rewrite `X-Forwarded-For`) · proudest (the OTP security chain, all demoable) · weakest (notification transport; named, with a fix path) · next week (push, object storage, cursor pagination, the vault/admin strangler slices).
